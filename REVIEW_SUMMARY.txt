VANCITY LENS - PERFORMANCE & SCALABILITY REVIEW SUMMARY
========================================================

ANALYSIS SCOPE:
- API: FastAPI application (6,349 Python LOC across 27 modules)
- Database: PostgreSQL 16 + PostGIS + pgvector
- Frontend: Next.js (TypeScript)
- Stack: Bill 47 entitlement engine + Intelligence layer + Neighborhood scorecards

CRITICAL FINDINGS:
==================

1. DATABASE CONNECTION POOL UNDERSIZED
   Current: min_size=2, max_size=10
   Impact: Exhaustion at 50+ concurrent requests
   Fix: Increase to max_size=25-100 (env-configurable)
   File: /api/db.py

2. MISSING COMPOUND INDEXES
   Missing: (signal_type, neighborhood, event_date), (document_id, chunk_index), etc.
   Impact: Sequential scans on intelligence signals and document chunks
   Performance: 10-20x slowdown vs indexed queries
   File: /db/007_intelligence_layer.sql (add 4 indexes)

3. N+1 QUERIES IN NEIGHBORHOOD SCORING
   Issue: 4 separate queries per neighborhood → 88 queries for 22 neighborhoods
   Impact: 880ms-4,400ms latency per /neighborhoods/scorecards request
   Fix: Single JOIN query + Redis cache (5-minute TTL)
   File: /api/intelligence/neighborhoods.py:242-310

4. SERIAL EMBEDDING/EXTRACTION PIPELINE
   Current: Document-by-document processing, chunk extraction forced to batch_size=1
   Impact: 1,000 documents = 10+ hours continuous processing
   Fix: asyncio.gather() for parallel chunk embedding, Semaphore-controlled LLM extraction
   Files: /api/intelligence/embeddings.py, routes.py:419-471

5. NO RESPONSE CACHING
   Missing: Cache for TOA GeoJSON, opportunity markers, neighborhood scorecards
   Impact: Same query recomputed every time (30s for TOA GeoJSON)
   Fix: Redis cache with 5-min/24-hour TTL
   File: New /api/cache.py + modifications to endpoints

6. INADEQUATE HEALTH CHECKS
   Current: /health endpoint returns {"status": "ok"} without checking dependencies
   Impact: Kubernetes can't detect DB pool exhaustion or API key misconfiguration
   Fix: Add /ready endpoint that checks database, cache, and API keys
   File: /api/main.py

7. NO REQUEST RATE LIMITING
   Current: Unlimited requests to chat/extraction endpoints
   Impact: 100 concurrent chat requests = 100× Anthropic API calls (hits rate limit)
   Fix: slowapi middleware or custom Semaphore-based rate limiter
   File: New /api/middleware/rate_limit.py

8. DOCKER RESOURCE LIMITS ABSENT
   Current: No memory/CPU limits in docker-compose.yml
   Impact: Uncontrolled resource consumption; no multi-tenant safety
   Fix: Add resource limits/reservations for db, api, redis, frontend
   File: docker-compose.yml

SCALABILITY GAPS:
=================

At 10x Scale (10,000 documents, 1,000 concurrent users):
- Pool exhaustion: System becomes unresponsive
- Document processing: 100+ hours instead of 10 hours
- Cache miss latency: 30s+ for GeoJSON endpoints
- API rate limits: Anthropic/Cohere will throttle requests

At 100x Scale (100,000 documents, 10,000 concurrent users):
- Complete system failure without infrastructure upgrades
- Connection pooling proxy (PgBouncer) required
- Message queue (Celery) for background jobs
- Read replicas for reporting queries
- Kubernetes with autoscaling
